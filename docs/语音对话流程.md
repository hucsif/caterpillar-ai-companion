# 语音对话流程 (ASR → LLM → TTS)

## 架构总览

**固件只负责音频采集/编码/发送和接收/解码/播放。ASR、LLM、TTS 全部在云端网关完成。**

```
[麦克风] ──PCM采集──▶ Opus编码 ──▶ WebSocket ──▶ 云端网关
                                                      │
                                              ASR(Whisper) + LLM + TTS
                                                      │
[喇叭]   ◀──Opus解码 ◀── WebSocket ◀── 云端网关 ◀────┘
```

---

## 一、设备状态机

11 个状态，定义在 `device_state.h`：

```
Unknown → Starting → WifiConfiguring → Activating → Idle
                                                   ↕
                                          Idle ←→ Connecting ←→ Listening ←→ Speaking
```

主要转换表：

| 从 | 到 |
|---|---|
| Idle | Connecting, Listening, Speaking（唤醒词/按键/网关下发） |
| Connecting | Listening（音频通道打开成功）、Idle（失败） |
| Listening | Speaking（TTS 开始）、Idle（停止/关闭） |
| Speaking | Idle（TTS 结束）、Listening（实时模式/打断） |

每次状态转换通过 `DeviceStateMachine::NotifyStateChange()` 通知主事件循环。

## 二、启动到空闲流程

1. **Application::Initialize()** — 初始化显示屏、音频服务、状态机回调
   - `on_send_queue_available` → 触发 `MAIN_EVENT_SEND_AUDIO`（主循环发音频）
   - `on_wake_word_detected` → 触发 `MAIN_EVENT_WAKE_WORD_DETECTED`
   - 状态变更监听 → 触发 `MAIN_EVENT_STATE_CHANGED`

2. **网络连接** → 进入 `Activating` 状态 → 启动 `ActivationTask`
   - 检查固件/资源版本
   - 调用 `InitializeProtocol()` 建立 WebSocket 连接

3. **InitializeProtocol()** — 创建 `WebsocketProtocol`，注册 5 个回调：
   - `OnConnected` — 关闭告警
   - `OnNetworkError` — 显示错误
   - `OnIncomingAudio` — 仅在 Speaking 状态时，将 Opus 包推入解码队列
   - `OnAudioChannelOpened` — 性能模式
   - `OnAudioChannelClosed` — 低功耗模式，回到 Idle
   - `OnIncomingJson` — 处理 `stt`、`llm`、`tts`、`listen` 等 JSON 消息（见第三章）

4. **协议握手** — 发送 hello（Opus 16kHz 单声道，MCP 特性），等待服务端 hello 回复（含 session_id）

## 三、网关到设备的 JSON 消息

### 3a. `stt` — 语音识别结果

```json
{"type":"stt","text":"用户说的话"}
```
→ 底部栏显示为 `"user"` 消息（纯展示，网关已转发给 LLM）

### 3b. `llm` — LLM 情绪

```json
{"type":"llm","emotion":"happy"}
```
→ `display->SetEmotion()` + `board.OnEmotionChanged()`（同步到矢量表情）

### 3c. `tts` — TTS 生命周期

| 子状态 | 含义 | 设备动作 |
|--------|------|----------|
| `"start"` | TTS 开始 | 切换到 Speaking，触发嘴巴动画 |
| `"sentence_start"` | 单句开始 | 显示 assistant 文字 |
| `"stop"` | TTS 结束 | 回到 Idle（**不自动回 Listening！**），停止嘴巴动画 |

注意：TTS 结束后回到 Idle 而非 Listening，需要网关显式下发 `listen` 或用户触发下一次对话。

### 3d. `listen` — 网关下发拾音指令

```json
{"type":"listen","state":"start","profile":"voice"}
{"type":"listen","state":"stop"}
```
→ 网关可通过 MCP 工具远程触发设备拾音

## 四、上行音频路径（设备 → 网关，ASR 输入）

### 4a. 拾音触发方式

- **唤醒词** `"你好小智"` → `HandleWakeWordDetectedEvent()`
- **按键/触摸** → `HandleToggleChatEvent()`
- **网关下发** `{"type":"listen","state":"start"}` → `HandleStartListeningEvent()`

### 4b. 进入 Listening 状态后

```
状态变为 kDeviceStateListening
  → SendStartListening()         通知网关
  → EnableVoiceProcessing(true)  启动 AFE 音频前端（降噪/VAD/AEC）
  → 关闭唤醒词检测               已经在听了
  → 播放 OGG_POPUP 提示音
```

### 4c. 数据流（3 个 FreeRTOS 任务协作）

```
audio_input 任务 (核心0, 优先级8)
  │ 每 10ms 从 I2S 读取 160 采样点 (16kHz 单声道)
  ├── 送唤醒词模型（如果启用）
  └── 送 AFE 管线（VAD+AEC+降噪）
        │
        ▼ PCM 帧 (60ms = 960 采样点)
  audio_encode_queue
        │
        ▼
opus_codec 任务 (优先级2)
  │ esp_opus_enc 编码
        │
        ▼ Opus 包
  audio_send_queue
        │
        ▼ on_send_queue_available 回调
  主事件循环 MAIN_EVENT_SEND_AUDIO
        │ protocol_->SendAudio()
        ▼
  WebSocket 二进制帧 → 云端网关
```

### 4d. 两种采音模式

| 模式 | 路径 | 用途 |
|------|------|------|
| `voice`（默认） | AFE 管线（VAD/AEC/降噪）→ Opus | 正常对话 |
| `raw` | 裸 PCM → Opus，绕过 AFE | 服务端分析 |

## 五、下行音频路径（网关 → 设备，TTS 播放）

### 5a. 进入 Speaking 状态

```
网关 {"type":"tts","state":"start"}
  → 状态变为 kDeviceStateSpeaking
  → 关闭语音处理（停止采音）
  → 重置解码器（清空队列）
  → 启用唤醒词检测（允许打断）
  → board.OnTtsStart()（嘴巴动画）
```

### 5b. 数据流

```
网关 Opus 音频 → WebSocket 二进制帧
  │ OnIncomingAudio (仅 Speaking 状态接受)
  ▼
audio_decode_queue
  │
  ▼
opus_codec 任务
  │ esp_opus_dec 解码
  │ 可选重采样
  ▼ PCM 帧
audio_playback_queue
  │
  ▼
audio_output 任务 (优先级4)
  │ codec->OutputData()
  ▼
I2S → 喇叭
```

### 5c. 打断和结束

- **唤醒词打断**：`AbortSpeaking(kAbortReasonWakeWordDetected)` → 清空发送队列 → 重新开始 Listening
- **按键打断**：`HandleToggleChatEvent()` → 回到 Idle
- **正常结束**：网关 `{"type":"tts","state":"stop"}` → 回到 Idle

## 六、完整对话时序

```
设备状态                  网关消息                        设备动作
════════                  ════════                        ════════

[Idle]
  用户说"你好小智" ────────────────────────────────── 唤醒词触发
  → [Connecting]                                       打开音频通道，发送 hello
                                                       收到服务端 hello (session_id)
  → [Listening]                                        SendStartListening
                                                       AFE 启动，麦克风采音
                                                       Opus 编码 → WebSocket 发送
                           ◄── Opus 音频流 ──────────  实时发送

                           网关 ASR 识别完成
                           ──▶ {"type":"stt",
                                 "text":"今天天气"} ──  显示 user 消息
                           网关 LLM 推理完成
                           ──▶ {"type":"llm",
                                 "emotion":"happy"} ──  更新表情
                           ──▶ {"type":"tts",
                                 "state":"start"} ──
  → [Speaking]                                        停止采音，重置解码器
                                                      嘴巴动画开始
                           ──▶ {"type":"tts",
                                 "state":"sentence_start",
                                 "text":"今天..."} ──  显示 assistant 消息
                           ──▶ Opus TTS 二进制 ──▶  解码 → 播放 → 喇叭
                           ──▶ {"type":"tts",
                                 "state":"stop"} ──
  → [Idle]                                            嘴巴动画停止
                                                      唤醒词重新启用
                                                      (等待下一次触发)
```

## 七、任务模型

| 任务 | 优先级 | 核心 | 职责 |
|------|--------|------|------|
| 主事件循环 | 10 | any | 状态机、发音频、UI 更新 |
| `audio_input` | 8 | 0 | 每 10ms 读麦克风，送唤醒词/AFE |
| `audio_output` | 4 | any | 取播放队列，写 PCM 到 I2S |
| `opus_codec` | 2 | any | 编码 PCM→Opus（上行），解码 Opus→PCM（下行） |

队列容量：
- `audio_encode_queue`：最多 2 个 PCM 帧
- `audio_send_queue`：最多 40 个 Opus 包（约 2.4 秒）
- `audio_decode_queue`：最多 40 个 Opus 包
- `audio_playback_queue`：最多 2 个 PCM 帧

---

## 八、关键设计决策

1. **WebSocket 常驻**：音频通道关闭后 WS 不断开，MCP 工具（LED/舵机/表情）在 Idle 时也能用
2. **TTS 结束不回 Listening**：防止 TTS 管线卡顿后误录环境音，需要显式触发下一轮
3. **session_id 校验**：防止过期网关连接的消息被误处理
4. **双采模式**：voice 模式走 AFE（降噪），raw 模式裸采给服务端处理
5. **Speaking 时可打断**：AFE 唤醒词在 TTS 播放期间仍工作
